# True Motion 0.17.0 — общая глубина, повторения, связи и ветвление рига

Это первая частичная реализация двух пунктов roadmap AbsentMotion 5.0. Полное соответствие roadmap не заявляется. Все новые настройки находятся в свойствах слоя → **Моушн-графика**, без дополнительных диалогов.

## Общая 3D-глубина

В основной композиции выберите любой визуальный слой → **Моушн-графика → 3D-сцена → Общая глубина**. По умолчанию режим выключен. Камера, Z и наклон задаются существующими инструментами. Без камеры используется стандартная перспектива композиции.

Плоские слои, отдельные грани 3D-моделей и отдельные спрайты частиц в режиме «3D сцены» используют один нативный буфер глубины. Пересекающиеся наклонённые плоскости и грани моделей могут закрывать друг друга в разных частях кадра. Глубина интерполируется с учётом перспективы, геометрия отсекается у камеры; прозрачные texel не перекрывают задние объекты. Общий направленный свет с азимутом, высотой, интенсивностью и фоновым освещением действует на модели и сохраняет направление при повороте камеры.

Ограничения первой версии:

- Scatter/Fracture, группы и модели с дополнительными эффектами компонуются как плоские поверхности. Эффекты камеры (туман/ГРИП) на моделях также переводят их в плоскую поверхность. Общий свет пока действует на модели; нет теней, точечных источников или PBR.
- Слои с clipping mask и режимами наложения, зависящими от фона, переводят весь кадр на прежний рендер, чтобы сохранить его композицию. 3D-геометрия внутри групп не пересекается с внешней сценой.
- Хранятся четыре ближайших полупрозрачных фрагмента в каждой точке; более дальние прозрачные поверхности могут пропадать. Для текстур моделей и частиц используется разрешение до 2048 px. Нет сглаживания геометрических краёв в новом проходе.
- Буфер рассчитан максимум на 8,5 млн пикселей видимой области; для большей области используется прежний рендер. Новый CPU-проход и чтение изображений с GPU требуют дополнительной памяти и могут заметно замедлить предпросмотр и экспорт.
- Выбор объекта мышью/касанием по-прежнему использует существующие границы и порядок слоёв: точный выбор ближайшей грани 3D-модели не реализован.

Таким образом, пункт Real 3D реализован частично: общая глубина есть для плоскостей, моделей и частиц; объёмные части эффектов ещё не подключены к ней.

## Повторения с отдельными смещениями

В **Моушн-графика → Повторения** задайте число экземпляров, включая оригинал (1–200), или добавьте копию кнопкой **+**. Выберите номер экземпляра в панели. Для каждой копии независимо задаются XYZ, поворот, множители масштаба и прозрачности, а также задержка анимации в кадрах. По умолчанию новые копии разнесены на 100 px по X.

Содержимое, эффекты и ключи оригинала обновляют все его повторения. ID вложенных слоёв и костей стабильны между изменениями. Смещения можно менять в этой панели или обычной трансформацией/перетаскиванием копии во вьюпорте; перемещение клипа меняет задержку. Обрезка длительности делает копию независимой. **Сделать независимой** оставляет вычисленную анимацию и разрывает связь. Удаление оригинала сохраняет копии как независимые слои. Копии рига создавайте из группы, содержащей весь риг.

## Связи значений

В **Моушн-графика → Связи значений** выберите изменяемый канал, слой-источник, его канал, множитель, смещение и задержку. Формула: `значение = источник(время − задержка) × множитель + смещение`.

Поддерживаются отдельные оси трансформации и числовые параметры фигуры/эффектов. Единицы параметров сохраняются; угол skew использует внутренние радианы. Векторы связываются по компонентам. Можно строить цепочки; циклы отвергаются. Изменение источника обновляет зависимые значения и повторения. Числовая анимация компилируется с частотой проекта в обычные ключи, поэтому предпросмотр и экспорт используют одинаковые данные. Это сохраняемая связь, а не однократная команда bake. Редактировать связанный компонент следует через источник или панель связи.

Ссылки на параметры эффектов следуют за эффектом при перестановке. Удаление источника/эффекта разрывает связь, оставляя вычисленную анимацию. **Отвязать, сохранив анимацию** делает то же вручную. Связи работают внутри одной композиции; параметрами повторений управляет оригинал. Общий предел — 500 000 вычисленных отсчётов связей в одной композиции.

## Риг: таз, ноги и несколько ветвей

Новая ветвь может начинаться в начале, конце или середине существующей кости. У одной кости может быть несколько дочерних ветвей. Это позволяет одновременно связать голову, обе руки и обе ноги с телом. Кость, выбранная во вьюпорте, имеет приоритет при совпадении суставов.

Рисование следующей ветви больше не переносит уже связанное тело на новую кость. Нажатие кости только выбирает её. Чтобы привязать деталь к выбранной кости, выберите деталь во вьюпорте/таймлайне и нажмите **Привязать выбранный слой** в панели вьюпорта. Первая кость на ещё не привязанной детали привязывает её сразу. FK/IK работают существующим способом; IK по-прежнему предназначена для цепочки из двух последовательных костей.

## Постоянная подпись preview

С этой версии сертификат закреплён в `docs/PREVIEW_CERTIFICATE_SHA256.txt`. Сохранён ключ локальных сборок 0.15/0.16; он используется снова. Публикация проверяет подпись и не создаёт случайный ключ вместо постоянного. Закрытый ключ не находится в репозитории или релизных файлах.

Ключ прежних APK из отдельных GitHub Actions запусков не сохранялся: восстановить его из APK нельзя. Если установлена такая сборка, у неё может быть другой сертификат. Перед переустановкой экспортируйте свои проекты средствами приложения. Следующие preview, подписанные закреплённым ключом, обновляют друг друга обычным способом.

Для CI владелец может один раз добавить секрет `TRUE_MOTION_PREVIEW_KEYSTORE_BASE64`: Base64 резервной копии постоянного keystore (alias `androiddebugkey`, пароли `android`). Это preview/debug-ключ, не production upload key. Доступ текущего GitHub Connector к Actions Secrets возвращает 403, поэтому секрет не добавлен автоматически. Альтернатива уже реализована: CI сначала выпускает проверенный unsigned APK (`prepare_only`), затем он подписывается постоянным ключом. Публикация через `validated_run` проверяет успешный запуск этого же workflow, коммит, контрольную сумму артефакта и побайтовое совпадение APK с проверенной CI-сборкой (кроме файлов подписи). Это также избегает различий DEX-метаданных между локальной и CI-средами. Временная ветка содержит только публичный подписанный APK и удаляется после публикации.

## Проверка и границы

Локальный полный прогон: 1737 JVM-тестов, 1711 пройдено, 26 пропущено, ошибок нет. После последнего уточнения ветвления рига повторно пройдены 18 профильных тестов и чистая сборка APK. Итоговый полный прогон для опубликованного коммита выполняет CI.

Проверки ядра глубины: пересечение треугольников с противоположным порядком подачи, обычная и additive-прозрачность, отверстия в текстуре, стыки спрайтов, отсечение у камеры, ортографическая/перспективная интерполяция. JVM-тесты проверяют временные связи, цепочки/циклы, отдельные оси, удаление и перестановку источников, повторения вложенных ригов и ветвление тела на пять деталей. Публикация сверяет содержимое APK с исходной CI-сборкой и сертификат.

Новые жесты и Android GPU-проход не проверены на физическом устройстве или эмуляторе в этой среде. Компиляция движка и автоматические проверки не заменяют такую проверку; релиз остаётся экспериментальным preview.


Для будущей проверки на устройстве добавлен и скомпилирован `Depth017Probe`: реальные пересечения плоскостей через GPU, независимость от порядка слоёв, прозрачность и поворот камеры. Выполнение в этой среде недоступно. После установки основного и androidTest APK можно запустить отдельно для Vulkan/Graphite и OpenGL:

```sh
./gradlew -PtrueMotionNativePrebuilt=true :app:assembleCompatDebugAndroidTest
adb shell am instrument -w -e depth017 true app.truemotion.test/app.truemotion.port.PortInstrumentation
adb shell am instrument -w -e depth017 true -e backend gl app.truemotion.test/app.truemotion.port.PortInstrumentation
```

PNG и JSON записываются в `files/depth017-validation` или `files/depth017-gl-validation` приложения. Во вьюпорте Graphite используется промежуточная поверхность, чтобы захват слоёв для общего буфера не затрагивал активную swapchain-поверхность.
