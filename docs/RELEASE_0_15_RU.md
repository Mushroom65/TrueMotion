# True Motion 0.15.0 — библиотека, риги и модели

Экспериментальный выпуск для проверки новых инструментов основного редактора. Это первая версия ригов из отдельных деталей, а не полная реализация Moho.

## Библиотека проекта

Откройте **+ → Библиотека** (верхняя строка вкладок прокручивается).

1. Нажмите **Добавить медиа**, выберите изображения, видео или аудио. Файлы остаются в библиотеке, даже если не используются слоями. Копирование файлов в проект учитывает настройку сохранения локальных копий; без неё нужен доступ к исходному файлу.
2. **Добавить в сцену** вставляет обычный слой на текущем кадре.
3. Чтобы менять изображение или видео по ключам, выберите медиаслой на таймлайне, откройте библиотеку, установите кадр ползунком и нажмите **Заменить на этом кадре ◆** у нужного файла. Изображение удерживается до следующего ключа, без смешивания источников. Аудио можно хранить и добавлять как слой; ключи замены аудио пока не реализованы.
4. Кнопки с ромбами переводят к ключам; **Удалить ключ замены** продлевает предыдущую экспозицию. Начальная экспозиция сохраняется. Операции поддерживают Undo/Redo основного редактора.
5. **Удалить** убирает файл из библиотеки, сохраняя его в слоях, которые его используют. Неиспользуемые файлы библиотеки входят в `.absproj` / `.alight` пакет вместе с проектом.

Слой с заменами становится вложенной группой с обычными клипами. Сохраняются внешние трансформации, родитель и эффекты. Геометрия остаётся общей, поэтому новое медиа заполняет прежний контур. Каждый видеоключ запускает видео с начала со скоростью 1× и зацикливанием. Прежние подрезка/скорость исходного видео не переносятся на дорожку замен. GIF в этом инструменте рассматривается как статическое изображение; обычная вкладка «Медиа» сохраняет существующий импорт анимированного GIF.

Если вручную отредактировать содержимое группы экспозиций, она становится обычной группой: дорожка автоматических замен отсоединяется, чтобы последующие изменения не затёрли ручной монтаж. Замены добавляются к обычным медиаслоям и уже созданным дорожкам замен.

## Риги из отдельных слоёв

Откройте **+ → Риги и модели → Кости**.

- Создайте корневую кость, выберите её в списке, затем добавляйте дочерние. Новая дочерняя кость присоединяется к концу родительской. Схема показывает скелет и выбранную кость.
- Чтобы привязать медиа, фигуру, текст или группу: закройте окно, выберите один или несколько слоёв на таймлайне, снова откройте вкладку, выберите кость и нажмите **Привязать к этой кости**. Используется существующий пересчёт родительских координат с сохранением анимации. **Отвязать** сохраняет мировое положение.
- Ползунок поворота поддерживает ключи. При включённом **Анимировать ключами** сохраняется исходный поворот в начале и записывается поза текущего кадра. Если выключить переключатель, значение заменит всю дорожку поворота.
- **Выбрать кость на таймлайне** открывает обычные инструменты трансформации. Можно двигать сустав, менять масштаб, длительность и ключи. Удаление кости использует существующее отсоединение дочерних слоёв.
- Длина кости — длина схемы и точка присоединения новых дочерних костей. Изменение длины не передвигает уже существующие суставы: их положение меняется через трансформацию.
- Для дочерней кости доступна **IK двух костей**. X/Y задаются относительно начала родительской кости в системе координат её родителя. Цепочка должна иметь масштаб 1, не иметь skew и иметь дочерний сустав в `(длина родителя, 0)`. Недостижимые цели ограничиваются длиной цепочки; можно сменить сторону сгиба. IK записывает обычные ключи поворота, а не живое ограничение на цель.
- **Запомнить исходную позу** сохраняет позу всех костей текущей сцены; восстановление учитывает режим ключей.

Это жёсткая привязка деталей. Взвешивание вершин, mesh/Smart Bone-деформация, живые IK-цели, ограничения суставов и импорт `.moho` не реализованы. Векторный редактор не изменялся.

## Сохраняемые модели

В той же вкладке откройте **Сохранённые модели**.

- Задайте имя и сохраните выбранный риг. Сохраняются родители и связанные дочерние слои. Без выделения сохраняются все визуальные слои сцены.
- Медиа копируется в личную папку модели. Если скопировать файл нельзя, сохранение завершается ошибкой, а не создаёт модель с потерянными ссылками.
- Добавление модели создаёт независимую вложенную группу с новыми ID и отдельными копиями медиа в проекте. Удаление сохранённой модели не ломает уже вставленный экземпляр.
- Откройте вставленную группу для изменения костей, рисунков и медиа. Экземпляр можно снова сохранить как новую модель.
- Доступны переименование и удаление сохранённых моделей. Обмен возможен через пакет проекта с вставленной моделью; отдельного формата экспорта моделей пока нет.

Для знакомства импортируйте `testdata/rig-model-demo.xml`: две кости с анимированными фигурами. Выберите нижнюю кость для IK или сохраните этот риг как модель.

## Проверка и сборка

Сборка: JDK 21, Android SDK 37, включённые в репозиторий ARM64 native-библиотеки.

```sh
./gradlew -PtrueMotionNativePrebuilt=true :app:testCompatDebugUnitTest :app:assembleCompatDebug
python3 tools/source_audit.py
python3 tools/verify_native.py
```

Локальная проверка завершена успешно: 1 717 JVM-тестов, 1 691 пройден, 26 пропущены по окружению, 0 ошибок; все 18 новых тестов пройдены. APK собран, версия/ABI/minSdk и подпись v2 проверены через aapt/apksigner. Аудит исходников и проверка хешей native-библиотек пройдены. Новые JVM-тесты покрывают границы экспозиций, замену/удаление ключей, перенос медиа при упаковке, локализацию моделей, копирование ID/родителей, FK и расчёт IK. Проверка интерфейса и рендера на Android-устройстве в этой сессии не выполнялась; данный выпуск помечен предварительным.

APK — совместимая ARM64 debug-сборка `app.truemotion`, minSdk 26. Она подписана локальным debug-ключом этой сборки. Возможность установки поверх прежнего APK с другой подписью не гарантируется. Перед изменениями установки сохраните проекты через экспорт пакета; удаление приложения удаляет его внутренние проекты, медиа и модели.
