# Нативное ядро True Motion Next 0.10 / AbsentMotion 4.0

`libamengine.so` в `app/native-prebuilt/arm64-v8a` теперь собрана из текущих C++ исходников. В ней реализованы буферы звуковых зависимостей, `lab.true.audioMotion`, компенсация якоря и его отображение, физика частиц и RGBA-путь кодирования для x86-эмуляторов. После обновления основы до 4.0 остальные восемь библиотек взяты из официального AbsentMotion 4.0.0 compatible APK; точные хэши и происхождение — TRUE_MOTION_PROVENANCE.json.

Нативный эффект не является шейдером трансформации и не меняет текстуру объекта: он работает в процессоре движения перед проекцией и отрисовкой. Его результат учитывают геометрия, выделение, группы, камера, PNG и видеоэкспорт. На кадр выполняется чтение двух соседних отсчётов огибающей; XML, массивы ключей и аудио не пересоздаются. Данные обновляются через JNI только после подготовки новой зависимости.

Android `AudioEffectRuntime` использует реальный OfflineMix, кэширует анализ с учётом выбранного слоя, его времени, скорости, громкости/аудиоэффектов и версии файла. Анализ и фильтрация не работают в потоке рендера. Изменённая сцена отменяет устаревший запрос. Для экспорта подготовка зависимостей завершается перед первым кадром. Буферы не записываются в XML, исходные ключи сохраняются.

## Сборка

Проверено в WSL Ubuntu 22.04 на Windows. Нужны git, Python 3, CMake, Ninja, C++ компилятор и Android NDK **30.0.16248370 (r30)**. Исходники Skia строго привязаны к commit `95ee33d7ec7791ab9c071675710a14fe6408ae4f`, GN — к `b2afae122eeb6ce09c52d63f67dc53fc517dbdc8`. Сохраняется patch `tools/skia-patches/vulkan-dst-read-copy.patch`.

1. Собери Skia compatible через `tools/build_skia.sh compat`, как в BUILD.md. На Windows желательно держать Skia и промежуточные файлы на файловой системе WSL. В .gitattributes для shell-скриптов и gradlew закреплён LF.
2. Задай `ANDROID_NDK`, при внешней Skia также `SKIA_DIR`, и необязательно `AM_NATIVE_OUT` для промежуточной папки.
3. Запусти `sh tools/build_engine_only.sh`. Он собирает только `libamengine.so`, не меняет остальные поставляемые библиотеки и не подменяет файл в `app/native-prebuilt` автоматически. Сохрани прежнюю библиотеку перед явной заменой.
4. Помести проверенную новую библиотеку в `app/native-prebuilt/arm64-v8a`, затем собери APK обычным Windows Gradle с `-PtrueMotionNativePrebuilt=true`.

Пример для отдельного Linux каталога сборки:

```sh
export ANDROID_NDK=/path/to/android-ndk-r30
export SKIA_DIR=/path/to/pinned/skia
export AM_NATIVE_OUT=/path/to/private/engine-build
export AM_BUILD_JOBS=3
sh tools/build_engine_only.sh
```

Флаг CMake `AM_ENGINE_ONLY` пропускает отдельные Whisper/ncnn/LAME цели, когда меняется только ядро. Полный upstream маршрут сборки всех библиотек остаётся доступен без него. Скрипт синхронизации пропускает неиспользуемые WebGPU headers вместе с Dawn; Vulkan/Skia зависимости остаются на исходных pinned commits.

Самостоятельный C++ тест семплера: `g++ -std=c++20 tools/tests/audio_signal_test.cpp -o /tmp/true-audio-test && /tmp/true-audio-test`.

Нельзя ставить прежнюю libamengine.so поверх 0.10: Kotlin использует добавленные JNI-методы, включая передачу RGBA-кадра в кодек. Проверки итогового APK включают загрузку всех 17 наших эффектов, нативную реакцию без ключей, PNG и MP4 с аудио, а также компенсацию якоря. На физическом телефоне версия пока не проверена.

В 0.5 также проверяется `tools/tests/particles_test.cpp`: аналитические случаи силы/drag, детерминизм, большие seed, четыре эмиттера, конус, притяжение и переиспользование физики при изменении цвета. encoder_copy.cpp включён в обе нативные конфигурации, чтобы новый JNI-путь присутствовал и в full, и в compatible сборке.

В ядре 0.9/0.10 также сохранены пространственные траектории и объединённый EncoderCopy с поворотом из основы 4.0 и RGBA-путём для x86. В 0.10 C++ код и готовая библиотека не менялись.

Проверка поставляемого ядра: python tools/verify_native.py. Поле sourceSHA256 в provenance сохраняет байты первоначального каталога сборки; sourceNormalizedSHA256 проверяет те же исходники после нормализации CRLF → LF, чтобы Windows- и Linux-checkout проверялись одинаково. Проверяются и остальные восемь библиотек.
